# WebGL Diorama

把一个主题变成一座**微缩场景（diorama）**：镜头贴近观察的小世界，边界清晰、细节密集、处处在动、可以把玩。产出两件东西：**场景提示词**（规格书）和**单文件 HTML**（实现）。

大多数用户写不出 [EXAMPLES.md](EXAMPLES.md) 那样的提示词。他们说得出**想看到什么、喜欢什么感觉**，说不出 InstancedMesh、IOR、Shader。所以分工是：**画面与玩法由用户挑，技术由你定**。你是递方案的美术指导——每一问都摆出具体、能想象出画面的选项，用户只需要挑。

## 起点

| 用户给了什么 | 路线 |
|---|---|
| 什么都没给（"做个好看的 3D 场景"） | 1 方案卡 → 2 → 3 → 4 → 5 |
| 一个主题 / 一句话想法 | 1 → 2 → 3 → 4 → 5，只问缺的 |
| 主题 + 较完整的描述 | 只问仍缺的维度（可能一题都不问）→ 3 → 4 → 5 |
| 完整提示词（"用 WebGL (Three.js r160 CDN) 创作…"） | 4 → 5 |
| 只要提示词（"写个提示词""不用实现"） | 1 → 2 → 3，交付提示词后结束 |

**提问方式**：用 AskUserQuestion，每轮一次调用；没有这个工具时，把题目和带字母的选项写进消息，请用户回复"1A 2C"这样的编号。第一次提问前用一句话告诉用户：选几个选项就能出方案，不会写提示词也没关系。用户在任何一轮说"你定 / 随便 / 都行"，该轮全取推荐项，继续往下走。

## 场景卡

给用户看的方案一律用场景卡——大白话，不出现技术名词，让用户一眼看懂会得到什么：

    「雪夜温泉」 写实 · 微观角落
    看到：山石间一汪冒着热气的露天温泉，石灯笼亮着暖光，四周积雪
    会动：雪花落进水里就化了，热气袅袅上升，一只小猕猴泡在水里打盹
    能玩：双击水面溅起水花，猴子睁眼转头看你；面板调落雪大小、灯光、时段
    彩蛋：空格——夜空绽放烟花，雪一下子下大了

## 步骤

### 1. 定画面

画面四个维度：**主题**、**风格载体**、**时段氛围**、**生灵**（住在场景里的小主角 + 空气里飘的东西）。读 [INSPIRATION.md](INSPIRATION.md)，按其中的规矩出题：

- 什么都没给：出一道**方案卡**题，3–4 张，每张一次定死四个维度。
- 给了主题或描述：已知的维度不问，只为缺的出一轮题。

完成标准：四个维度都有值——来自用户的选择、用户的原话，或"你定"时的推荐项。

### 2. 定玩法

玩法三个维度：**双击互动**、**空格彩蛋**、**面板调节**。按 INSPIRATION.md 第二轮出一轮题，同样只问缺的；选项从已定的画面里长出来。

完成标准：三个维度都有值；双击互动是一条完整因果链——用户动作 → 视觉效果 → 生灵的反应。

### 3. 起草并确认

1. 读 [PROMPT-TEMPLATE.md](PROMPT-TEMPLATE.md)，把前两步的选择填进模板。用户没选、也不必让用户选的部分（布局物件、材质、光源、Shader、技术要求）由你按主题补全；拿不准分寸时对照 EXAMPLES.md。
2. 先给场景卡，再用代码块给完整提示词。
3. 问下一步：「开始制作（推荐）」「调整一下」「只要提示词」。选"调整一下"就追问改哪里（换生灵 / 换彩蛋 / 更热闹 / 更安静，或直接说），改完重新给场景卡和提示词，再问一次。

完成标准：
- 模板每个槽都已填满，固定句原样保留；
- 提示词里每个元素都能在 [IMPLEMENTATION.md](IMPLEMENTATION.md) 的技法速查里找到做法，找不到的已换成能做的近似；
- 用户明确选了「开始制作」，或选了「只要提示词」（此分支到此结束）。

### 4. 实现

1. 把 `scaffold/` 整个复制到当前工作目录，目录名用英文 kebab-case（如 `snowy-onsen/`）。骨架已经实现所有固定交互和通用系统——**在骨架上改**。
2. 读 IMPLEMENTATION.md，按其中的改法、防穿模契约和性能要点实现。
3. 把提示词逐条拆成清单（每个物件、每条动态、每个光源、每个交互、每条技术要求各一项），做一项勾一项。
4. 在该目录运行 `node build.js`，生成 `index.html`。

完成标准：清单里每一项要么已实现，要么记下了"用什么近似实现"（如 SSS → sheen 近似）；`node build.js` 成功。

### 5. 验收

有 chrome-devtools MCP 时，用 `file:///` 打开 `index.html`：
- 控制台零报错（`Unsafe attempt to load URL file://…` 是 DevTools 在 file:// 下的噪声，不算）；
- 截图：画面主体、光影、氛围与场景卡一致；
- 依次验证 H（UI 淡出/淡入）、F（全屏）、空格（彩蛋）、双击（效果 + 生灵反应）、面板每个控件；
- 静置数秒读 FPS，≥ 55 达标。自动化浏览器常是软件渲染、帧率整体偏低：这时在同一浏览器里打开一份未改动的骨架构建作对比，差距不大即算达标，并在汇报里注明。

没有浏览器工具时，如实告诉用户哪些没实测。

向用户汇报：文件路径（双击用 Chrome 打开即可）、清单完成情况、所有近似实现、实测 FPS。用户同样说不出"还能怎么更好"，所以汇报末尾根据截图给 2–3 个具体的改进选项让用户挑（如"兔子毛再蓬松些""加一群萤火虫""月光再冷一点"），选中就回到第 4 步改。

完成标准：以上每项都有结果，汇报已发出。
